## 需要安排的改进

### 1. 历史记录超过 30 条后，旧记录无法从比较和报告页面选择

- **代码位置：** `backend/app/main.py` 的 `list_scans` 默认 `limit=30`；`frontend/src/api.ts` 的 `api.scans()` 不传分页参数；比较页和报告页直接使用该列表。
- **具体影响：** 保存超过 30 条检测后，数据库仍有旧记录，但 UI 的比较选择和报告列表只载入最近 30 条。用户无法从这两个页面选择更早的记录；首页统计也只反映这批返回记录。
- **建议处理：** 为列表 API 增加 offset/总数信息，并在历史相关页面提供分页或“加载更多”。这是功能边界，不会导致既有数据丢失。

### 2. 设置页关键操作缺少组件级回归测试

- **代码位置：** `frontend/tests/App.test.ts` 检查中文“设置”链接和 `/settings` 路由；`frontend/src/views/SettingsView.vue` 还包含配置保存、连接测试、清除配置和错误状态。
- **具体影响：** 路由存在或 HTTP 深链返回 SPA 页面，不能证明按钮会调用正确 API、显示错误或清除敏感输入。本轮没有可用的浏览器交互自动化入口，因此这些动作没有经真实浏览器点验。
- **建议处理：** 为设置组件补一组 mock API 的交互测试，覆盖初始状态、保存后清空密钥输入、测试失败提示和清除后状态刷新。

## 检查范围与边界

- **扫描安全：** 检查 `validate_target`、`PinnedBackend`、`PinnedTransport` 和 `fetch_page`；测试覆盖非 HTTP(S)、用户信息 URL、本机/私网解析、混合公网与私网 DNS 答案、固定 IP、危险重定向拒绝、超时和响应体上限。重定向由程序手动跟随并逐跳验证；请求使用 `trust_env=False`。
- **采集与持久化：** 采集器只发 GET；摘要响应头、Meta 和资源 URL，并仅在内存中保留 HTML 供规则匹配。数据库写入扫描摘要、技术、证据和用户主动生成的 AI 报告。
- **识别和比较：** 规则来自项目内 JSON；结果保留命中来源和内容，权重累加封顶；比较字段使用“本次未观察到”语义。
- **报告和 AI：** HTML 对标题、分类、证据、模型名和 AI 内容进行转义；AI Base URL 与扫描目标校验分开；API Key 用 `SecretStr` 接收并保存在服务内存中，测试确认不会返回或写入扫描历史。
- **前端安全：** AI 报告和扫描信号通过 Vue 插值呈现；在 `frontend/src` 和后端报告生成路径中没有发现使用 `v-html` 的地方。
- **运行环境：** 本机服务只绑定 `127.0.0.1`，没有账号认证；不要把它暴露到共享网络。
