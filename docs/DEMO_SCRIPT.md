# 答辩演示动线卡 [实测 Measured]

这份动线卡帮你在五分钟内讲清楚这个系统是什么、怎么做、为什么可信。全部台词都已写在屏幕上，你只需要照着点、照着念。

## 开场（30 秒，背下来）

「这个工具回答一个简单的问题。一个网站是用什么技术做的？它只发一次普通的网页访问请求，就像浏览器打开网页一样，然后从响应里找线索，给出带证据的判断。它最特别的地方是，结论必须给依据，而且依据让你看，你可以自己验证。」

## 演示步骤（跟着点）

1. **打开首页**（`./scripts/start.sh` 已启动，浏览器开 `http://127.0.0.1:8000`）。
   念「首页这几条记录是提前扫好的真实网站，断网也能看。」
2. **点开 WordPress 官网那条记录**。
   念「结论面板说『可以确认使用了 WordPress』。依据是它页面的声明里白纸黑字写了 WordPress，像身份证，不是猜的。」
   顺手点「证据」页。「每一条结论都能追到具体的响应字段，老师可以核对。」
3. **回到首页，现场输入 `bilibili.com`，点开始检测**。
   念「现场扫一个，大约几秒到三十秒。」出结果后指着结论面板。「发现的每一项都标了把握程度。白纸黑字的才算确认，只是旁证的会注明仅供参考。」
4. **如果被问到 AI**。
   念「AI 在这个系统里只负责解读证据，不负责判断技术是否存在，判断权在规则引擎。而且发送前有确认提示，密钥只存在内存里。」

## 老师可能问的问题 [实测 Measured]

- **「扫不出来怎么办？」**「它会诚实地说没发现线索。没发现不等于没用，有些踪迹藏在接口响应里，一次普通访问看不到。宁可空着也不编造，这是设计原则。」
- **「和 Wappalyzer 这类工具有什么区别？」**「思路同类，但它们只给答案。我的工具给答案加证据链，每个结论可以自己核实。」
- **「为什么有的网站扫不出来或超时？」**「扫描器出于安全考虑禁止走代理、只访问公网地址，本机网络慢时会超时。这是防内网扫描的安全设计，不是缺陷。」
- **「能扫内网机器吗？」**「不能。域名会先解析成 IP，只要落在私网或本机段就拒绝访问。」
- **「规则能扩充吗？」**「规则是一个 JSON 文件，加一条规则不用改一行代码。现在有 61 条，覆盖常见的服务器、框架、建站工具和统计脚本。」

## 兜底

现场网络不行就只演示第 1、2 步（离线数据），照样完整。

机房电脑缺 Node.js 或 uv 时，改用零依赖离线包。命令是 `python3 scripts/serve-offline.py`，打开 `http://127.0.0.1:8010`。界面、12 条真实演示记录、结论与证据、历史对比、报告导出都在，只是不发外部请求。
