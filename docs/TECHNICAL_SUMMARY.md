## 二、核心技术手段与实现路径 [实测 Measured]

系统只发起一次普通的公开 GET 请求。整个链路可以拆成六步。

1. 输入网址。用户可以直接输入裸域名，例如 `jd.com`。系统自动补上 `https://` 前缀。
2. 安全校验。`security.py` 解析域名，逐条检查 DNS 返回的 IP。私网、环回与保留地址一律拒绝。
3. 公开采集。`fetcher.py` 手动处理跳转，最多跟踪 5 次。每次跳转重新校验目标地址。
4. 信号提取。解析响应中的白名单响应头、页面声明、脚本地址、样式地址与网页标题。
5. 规则匹配。`detector.py` 用 61 条正则规则对信号逐条打分。分数封顶 100 分。
6. 结论与展示。至少有一条直接证据才算可以确认。只有旁证的项标为仅供参考。

采集器使用 `trust_env=False`。这条设置禁止读取系统代理环境变量。它和 IP 校验共同构成防 SSRF 边界。响应体上限为 5 MiB，超时为 30 秒。这三项参数都写在 `security.py` 与 `fetcher.py` 中。

证据分成两类，界面和导出报告使用相同的中文标签。

| 标签 | 判定依据 | 可信度处理 |
| :--- | :--- | :--- |
| 白纸黑字 | 响应头或页面生成器声明 | 可以当作确认结论 |
| 旁证推断 | 脚本文件名或页面关键字 | 只作参考，不下定论 |

界面按信息优先级重排。检测结论置顶，下面依次是网站档案带、资源清单、识别结果与分类统计。每条信号附带一句人话解读。导出的 HTML 报告包含同样的信息，配色与产品界面一致。

## 三、系统调整测试与故障排查过程 [实测 Measured]

调试中遇到的主要问题与处置办法如下。全部是本机复现过的真实故障。

| 现象 | 根因 | 处置 |
| :--- | :--- | :--- |
| 前端 7 个测试文件全挂 | 宿主注入 `NODE_OPTIONS`，vitest worker 握手超时 | 一键脚本开头清除该变量 |
| 后端第二次跑报 `EEXIST` | 宿主注入 `PYTHONPATH`，shim 重复建临时目录 | 一键脚本同时清除该变量 |
| 首页预加载 540 kB 图表分块 | `manualChunks` 把 Vue 运行时吸进手工分块 | 删掉强制分块，改回按需加载 |
| 禁用按钮残留浅蓝 | Element Plus 禁用态使用独立颜色变量 | 补 hover、active、disabled 三组覆盖 |
| 类别中文在页面空白 | `TechnologyOut` 缺字段，被响应模型过滤 | schema 补 `category_label` 字段 |
| 删除 Tailwind 后构建失败 | 样式表还留着 `@import "tailwindcss"` | 同步删掉空转导入 |
| 空网址回车仍发请求 | 按钮禁用挡不住表单回车提交 | 提交函数增加空值守卫 |
| 新字段在接口里为空 | 旧服务进程没杀干净，仍在响应请求 | 循环清理端口上全部进程后重启 |
| GitHub 许可证显示为 Other | LICENSE 开头有自定义前言，平台识别不了 | 改为标准 GPL-3.0 开头 |

性能调整也有实测依据。删除强制分块后，首页预加载数量从 1 个降为 0 个。首屏 gzip 合计从 260.59 kB 降到 102.86 kB。最大分块从 540.47 kB 降到 458.82 kB，Vite 体积提示随之消失。

外部扫描曾连续出现 504。同机直连返回 200 用时 6.73 秒，走代理返回 200 用时 0.35 秒。根因是禁用代理叠加 10 秒超时。后来把超时放宽到 30 秒，百度等慢站点可以正常扫完。安全边界没有放宽。

## 四、工程管理方式 [实测 Measured]

版本库使用 Git，全部改动按单一主干提交并推送到 GitHub。每次改动都绑定一条可复验的结论。

- 一键验收脚本 `scripts/verify-all.sh` 依次执行后端测试、Ruff、前端测试和构建。
- 一键启动脚本 `scripts/start.sh` 负责依赖检查、演示数据初始化、启动服务与打开浏览器。
- 预扫脚本 `scripts/prewarm-demo.py` 幂等地写入 6 个知名网站的离线演示记录。
- 决策账本记录每条改动的假说、前后实测数据与经验，当前累计 17 条。
- 四项门禁覆盖交接单、散文、代码卫生与运行时验证，提交前要求全绿。

文档分工明确。`TEST_REPORT.md` 记录测试与实测数据，`API.md` 记录接口，`ARCHITECTURE.md` 记录架构。`DEMO_SCRIPT.md` 是现场演示动线，本文是技术总结。过程性文件放在 `.agents` 目录，不进入交付仓库。

## 五、质量控制措施 [实测 Measured]

质量控制以可复验为第一原则。任何结论都要能指出证据来源。

| 检查项 | 命令或手段 | 当前结果 |
| :--- | :--- | :--- |
| 后端单元与接口测试 | `pytest -q` | 23 项通过 |
| 后端静态检查 | `ruff check .` | 全部通过 |
| 前端组件测试 | `pnpm test` | 6 个文件 9 项通过 |
| 类型检查与构建 | `pnpm build` | vue-tsc 与 Vite 均通过 |
| 运行时门禁 | `pstack verify all` | 四项门禁全绿 |
| 浏览器实测 | Chrome 无头加 CDP | 1440 与 900 两档无溢出 |

安全边界单独验证。输入 `127.0.0.1:8000` 返回 400，提示禁止检测私网地址。输入不存在的域名返回 400，提示无法解析目标主机名。失败请求不写入数据库，历史总数保持不变。

依赖风险也做过核对。前端 `pnpm audit` 报 2 个中危，涉及开发期工具 glob 与 minimatch。Python 侧用 OSV 接口查了 35 个包，命中 pip 25.2 与 pytest 8.4.2 的公告。这些都在开发工具链，不进入运行产物。当前选择保留现状并记录，不擅自升级。

结论层做了分级。响应头和页面声明属于直接证据，可以确认。脚本命名和页面关键字属于间接特征，只标疑似。没有命中时如实说明未发现线索，并解释未发现不等于没有使用。

## 六、检测实验数据分析 [实测 Measured]

指纹规则库从 19 条扩充到 61 条。新增规则优先使用响应头这类直接证据。每条规则都做过正向与反向 fixture 验证。

真实网站抽样结果为可达站点 8 站命中，1 站零命中。另有 2 站超时，1 站连接失败。这几项属于本机直连网络边界，不计入识别失败。

| 目标 | 识别结果 | 证据类型 |
| :--- | :--- | :--- |
| wordpress.org | WordPress、Nginx 可确认，Google Analytics 疑似 | 生成器声明与 Server 头 |
| 淘宝 | Tengine | Server 头直接证据 |
| 搜狐 | OpenResty | Server 头直接证据 |
| 少数派 | Vue、Google Analytics、百度统计 | 页面特征与脚本地址 |
| 京东 | Nginx | Server 头直接证据 |
| B 站 | Vue 疑似 | 页面模板属性，属旁证 |
| 百度 | jQuery 与 Baidu BWS | 脚本地址为旁证，Server 头为直证 |

单次扫描还会记录响应耗时与页面大小。B 站实测耗时 2612 毫秒，页面 162.7 KB。这些读数来自 `fetch_page` 的计时与响应体长度，不是估算值。

百度曾出现零命中。逐条比对 19 条旧规则与百度响应，命中数为零。原因是百度使用自研 BWS 服务器，页面没有生成器声明，也没有常见开源组件特征。扩充规则后同一站点可以命中两项。这个案例说明零命中本身也是诚实的结果，不能靠猜测补齐。

## 七、改进措施与后续优化建议 [推导 Inferred]

以下属于基于现有实测的推导，尚未实现。

- 规则库可以继续扩充。新增规则只改 JSON 文件，不需要改动检测器代码。
- 纯客户端渲染站点首屏特征很少。后续可在受控环境引入无头浏览器提取动态 DOM 特征。
- AI 分析链路已经验通配置、密钥隔离与确认门禁。本机缺少真实模型端点，尚未做真实推理验收。
- 外部扫描受禁用代理约束。部署到直连条件更好的机器可以改善慢站点的成功率。
- 依赖公告集中在开发工具链。后续可在版本窗口稳定时统一升级。
- 批量资产巡查与定时复测是自然延伸方向，当前单机版本尚未覆盖。
