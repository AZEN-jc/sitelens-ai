# SiteLens AI 答辩讲解稿（5–8 分钟）

建议目标时长约 6 分 30 秒。方括号内容是演示动作提示，不必照念。只演示你有权分析的网站；若没有可用授权目标，不要伪造实时结果，可解释测试夹具并清楚标明它是测试数据。

## 0:00–0:45｜题目与问题

各位老师好，我的毕业设计题目是《基于 Python 与人工智能的网站技术特征识别与分析系统的设计与实现》。它关注一个具体问题：开发者通常只能看到网站公开返回的页面，却不容易快速整理页面暴露的技术线索。SiteLens AI 对授权网站采集有限的公开 HTTP 信号，用本地指纹规则给出技术候选和可追溯证据，并保存历史结果便于比较。

系统只做普通 GET 和公开信号分析，不做漏洞探测、登录绕过或访问控制规避。

## 0:45–1:30｜整体结构

系统由 Vue 3 前端、FastAPI 后端和 SQLite 组成。前端提交扫描请求；后端负责安全校验、HTTP 采集、规则匹配和持久化；浏览器再读取保存结果并展示。识别规则存放在 JSON 文件中，便于查看每种技术使用了哪些信号和权重。

[打开首页，指出输入框、授权确认和历史区域。]

## 1:30–2:40｜扫描和识别

一次扫描从前端的 ScanForm 开始，经 `/api/scans` 到后端 `create_scan`。后端先检查授权声明，然后调用 `fetch_page`。采集器检查 URL 和 DNS 地址，通过已验证的公网 IP 发起 GET；如果遇到重定向，会重新检查目标。采集只受限提取响应头、标题、Meta、脚本和样式资源等信号。

随后 `detect` 按 JSON 规则匹配这些信号。匹配结果不是只给出一个技术名称，还带有证据来源、实际命中内容、证据类型和权重。证据能够让用户回到公开响应，理解系统为什么作出这个判断。

[如有授权目标，提交一次扫描；打开一项技术的证据。如果没有授权目标，跳过实时提交，不要把测试夹具说成实时网站。]

## 2:40–3:35｜分数与安全边界

系统把命中规则的权重去重后累加，最高封顶 100；低于 40 是 low，40 到 69 是 medium，70 及以上是 high。这是本项目的内部规则分，不是统计概率，也没有经过大规模真实样本校准。

扫描器拒绝非 HTTP(S)、带账号密码的 URL 和解析到私网或保留地址的主机；它禁用代理，限制请求时间、重定向次数和响应大小。网页 HTML 仅在处理期间放在内存中，数据库保存必要摘要和证据，不保存整页。

## 3:35–4:20｜历史、架构和报告

历史比较把结果分成新观察到、当前未观察到、证据变化和证据相同。“未观察到”只说明本次响应没有匹配到，不足以证明网站移除了某项技术。架构图展示的是同一公开响应共同观察到的技术关系，所以是推测，不是网站内部部署图。

用户可以导出 JSON 或适合打印的 HTML；PDF 通过浏览器打印保存，不依赖服务端 PDF 引擎。

[如有两条已保存记录，演示比较；否则展示页面并说明需要两次记录才能比较。]

## 4:20–5:05｜AI 的职责

AI 是可选的解释功能。用户在设置中选择兼容服务后，分析前页面会显示将发送的结构化摘要并要求确认。AI 只收到扫描摘要和匹配证据，不收到整页 HTML；它负责解释结果，不参与技术是否存在的判定。API Key 只在后端进程内存中保留到服务重启，不写入数据库，也不会返回到页面。

[没有配置 AI 时如实说明这是可选路径，不临时填入或展示密钥。]

## 5:05–6:10｜测试与局限

测试包含 URL/DNS 和重定向安全、响应限制、规则与证据对应、未知信号、AI 的成功和失败处理、密钥清除、历史比较和报告导出。另有两个受控本地页面，测试时只替换了 DNS 校验以便请求测试服务器；生产扫描仍会阻止本机地址。

这些测试验证的是已覆盖的行为和受控样本，不证明系统可以识别所有网站。静态规则可能漏掉混淆、打包或只在服务器内部使用的技术；当前也不运行 JavaScript，所以动态渲染后的信号不在范围内。

## 6:10–6:45｜总结

这个系统把公开信号采集、规则识别、证据追溯、历史比较和可选 AI 解释连成了本地演示流程。设计重点是让识别结论可解释，并明确说明观察范围和不确定性。后续可以扩大并评估指纹样本、增加动态页面支持，并用标注数据研究评分校准；这些是后续工作，不是当前已完成能力。我的汇报到这里，谢谢各位老师。

## 常见追问

### 1. 高置信度是不是代表 85% 的概率？

不是。它是规则权重求和后按阈值划分的内部等级。当前没有基于有标签的大规模样本做概率校准，所以不能解释成百分比。

### 2. 为什么要保存证据，而不只保存技术名称？

证据说明结论来自哪个响应来源、命中了什么文本和使用了多少权重，便于用户复核，也能让误判更容易被定位。

### 3. 系统能看出网站隐藏的后端框架吗？

不能保证。只有网站公开响应中出现可匹配信号时才会报告；隐藏在服务端且未暴露的技术可能完全不可见。

### 4. DNS 检查后为什么还要固定 IP？

如果校验后再次按域名解析，解析结果可能变化。固定到刚校验的 IP 能缩小这段时间内目标被替换的风险；重定向目标也必须重新校验。

### 5. 为什么 AI 可以连本机服务，扫描器却不能？

扫描 URL 来自待检查输入，允许访问私网可能把工具变成访问内网的通道。AI Base URL 是用户主动配置的信任选择，两条请求路径使用独立校验规则。

### 6. AI 会不会把错误技术识别“确认”为正确？

不会。技术是否命中由规则引擎决定。AI 收到已有结果和证据，只负责解释；它的自然语言输出仍需结合证据复核。

### 7. “本次未观察到”说明网站删掉了技术吗？

不说明。页面可能变化、响应信号可能被隐藏或当前指纹不覆盖它。比较结果只描述两次观察差异。

### 8. 本地测试为什么能访问 127.0.0.1，而生产不行？

测试夹具通过 monkeypatch 替换了测试进程中的目标校验，以测试固定传输和识别流程。生产实现没有这个替换，仍会拒绝 loopback/私网地址。测试辅助路径不能当作生产功能。

### 9. 项目目前有哪些主要不足？

规则集规模有限、没有覆盖率和概率校准数据；不运行浏览器 JavaScript；本地单用户应用没有账号认证，不能暴露到共享网络。这些都应作为限制或未来工作说明。
